# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-file PowerShell script (`src/AzIPFetcher.ps1`, ~466 lines) that enumerates used and available private IPs across Azure VNets/subnets, scoped by subscription IDs, management groups, or subscription name patterns, and exports to CSV/JSON/HTML.

There is no build, no package manifest, no test suite, and no linter config. The only CI workflow (`.github/workflows/copilot-setup-steps.yml`) just pre-installs modules and only triggers on changes to itself — it never runs the script.

```bash
pwsh -NoProfile -Command '$e=$null;$t=$null;[System.Management.Automation.Language.Parser]::ParseFile("src/AzIPFetcher.ps1",[ref]$t,[ref]$e)|Out-Null; if($e){$e|%{"$($_.Extent.StartLineNumber): $($_.Message)"}}else{"PARSE OK"}'
```

Lint (PSScriptAnalyzer is *not* currently installed; install first if you want it):

```powershell
Install-Module PSScriptAnalyzer -Scope CurrentUser -Force
Invoke-ScriptAnalyzer -Path src/AzIPFetcher.ps1
```

Run (requires an interactive Azure login and Reader access on the target scope):

```powershell
./src/AzIPFetcher.ps1 -subIds 'sub1,sub2' -ExportCSV -OutputFolder "C:\Reports"
./src/AzIPFetcher.ps1 -subIds '@all' -ExportJSON
./src/AzIPFetcher.ps1 -MgGroupIds 'mg1,mg2' -Subpattern 'prod,test' -ExportHTML
```

Caution on `-Subpattern`: the README advertises glob syntax (`'prod*,test*'`), but that does not work. Values are passed through `[regex]::escape` and joined with `|`, so `prod*` becomes `prod\*` — a literal asterisk. `'prod*'` matches only names actually containing `*`, and silently `exit`s with "No subscriptions found". Use bare substrings instead (`-Subpattern 'prod,test'`), which match anywhere in the name, case-insensitively.

## Architecture and execution order

Everything is top-level script scope; functions are defined then invoked from one `try/catch` at the bottom (line ~415). Order matters and is non-obvious:

1. `Print-Banner` — ANSI RGB escapes, requires a terminal that supports them.
2. `Install-RequiredModules` — installs `Az.Accounts`, `Az.Network`, `Az.Resources`, plus `PSWriteHTML` **only if `-ExportHTML` was passed**. Adding an HTML-dependent feature means updating this conditional too.
3. `Connect-azure` — checks `Get-AzContext` + `Get-AzAccessToken`, falls back to `Connect-AzAccount` (`-UseDeviceAuthentication` on Unix).
4. `Initialize-FileName` — sets `$script:FilePath` to `<OutputFolder>/AvailableIPsInVNET_<ddMMyyyy_HHmmss>` with **no extension**; each exporter appends `.csv`/`.json`/`.html`. Creates the folder if missing; defaults to `$PSScriptRoot`.
5. `Get-workingcontext` — resolves scope into `$Script:subscriptions`. Management groups are walked breadth-first with a `System.Collections.Queue` over `Get-AzManagementGroup -Expand -Recurse`, collecting `/subscriptions` nodes. Disabled subscriptions are then filtered out by re-querying each one.
6. `Get-AvailableIPsInVNet` — called per subscription; appends to `$Script:results`.
7. Export switches, then a final `Format-Table` to console.

### Data flow convention

State moves through **script-scoped variables, not return values**: `$Script:results`, `$Script:subscriptions`, `$script:FilePath`. `Get-AvailableIPsInVNet` ends with `return $Script:results >$null` — the redirect deliberately swallows the value, and both `Get-workingcontext` and `Get-AvailableIPsInVNet` are called for their side effects. Do not refactor these into pure functions without updating every call site; the pipeline output is intentionally suppressed so it doesn't pollute console output.

### IP math

Subnet IPs are generated by converting the network address to a `UInt32` via `[BitConverter]` with `[Array]::Reverse` on both sides (little-endian round-trip), then incrementing across `1..(2^(32-prefix) - 1)`. Used IPs come from the subnet's `IpConfigurations`, mapped back to parent NIC resource IDs by splitting on `/ipConfigurations/`, de-duplicated, and filtered to IDs containing both `/NetworkInterfaces/` and the current subscription ID. Available = `Compare-Object` of all vs. used, then `[3..count]` to drop Azure's reserved addresses.

Azure-managed subnets (`GatewaySubnet`, `AzureBastionSubnet`, `AzureFirewallSubnet`, `AzureFirewallManagementSubnet`, `RouteServerSubnet`) short-circuit to the string `"N/A"` for counts and `"Undefined"` for the available list — so count fields are mixed `int`/`string` by design. Anything consuming those fields must tolerate both.

## Known defects in the current code

Do not treat these as intentional; they are real bugs worth fixing if you touch the surrounding code.

- **`src/AzIPFetcher.ps1:91`** — a stray `bn` token sits in the `catch` block of `Connect-azure`. The file parses fine, but `bn` is parsed as a *command invocation*, so it throws `CommandNotFoundException` at runtime on every path where the login fallback runs (i.e. whenever the user is not already authenticated).
- **`src/AzIPFetcher.ps1:375-387`** — `SubscriptionName`, `SubscriptionId`, and `ResourceGroupName` are commented out of the result object. Since the script's headline feature is multi-subscription scanning, exported rows currently cannot be attributed to a subscription or resource group.
- **`src/AzIPFetcher.ps1:349`** — `$AvailableIps[3..$AvailableIps.count]` indexes one past the last element (`.count` vs `.count-1`), appending a `$null`; it also assumes the first three entries of a `Compare-Object` result are the reserved ones.
- **`src/AzIPFetcher.ps1:256`** — `[regex]::escape` is applied to user-supplied `-Subpattern` values, which defeats the wildcard syntax documented in the README (see Commands above). Either strip/translate `*` to `.*` or update the docs.
- **`src/AzIPFetcher.ps1:287`** — a local `$results = @()` is dead; the real accumulator is `$Script:results`, which is never reset between subscriptions.

## Conventions

- Version lives in three places that must be kept in sync: the comment header, `$ScriptVersion` (line ~131), and the README change log.
- User feedback is `Write-Host` with colors: Cyan = section header, Green = success, Yellow = warning/info, Red = error.
- All script parameters are optional; exports are switches. Passing no scope parameter at all yields an empty subscription list rather than an error.
